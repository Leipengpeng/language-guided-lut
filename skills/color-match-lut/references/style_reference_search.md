# 从原片和风格描述自动查找参考

用户给出原片和一句风格描述就开始。先读原片判断光照与题材，再按用户的描述搜索、筛选、归纳和选图。用户明确给出的作品、段落、颜色、力度和保护项优先。只用文字搜公开样张，原片只在本地或宿主里判断场景，不上传给搜索引擎。

## 理解描述并搜图

- **片名**。核对正式中文名、原名、年份和版本。优先搜索该片实际画面，例如「片名 年份 剧照」「原名 film still」「原名 cinematography frames」。用户点名段落、年代或色彩工艺时，只在该范围统计。翻拍、续集、不同修复版分开。没有指定段落时，覆盖不同场景。
- **导演**。先用电影资料馆、发行方、官方片单或影展页核对身份和作品。选择两到三部有可靠画面的代表作，尽量覆盖不同作品并让样本量相近。搜「导演名 电影名 剧照」或「片名 director of photography stills」。只有跨影片反复出现的配色才称为导演的常见方向。作品之间明显分组时，分开看每部作品；从反复出现、且最贴合原片光照和题材的作品配色中选一组，交付时写清参考作品。证据只来自一部影片时，只将结论归到该片。
- **模糊风格、情绪或时代**。把「很有老港片的感觉」「干净清透」「自然一点」和原片的场景搭成摄影关键词，寻找实际照片或电影画面。尽量覆盖独立系列或来源。样本支持的是可用于这张原片的配色方向。
- **摄影师、胶片或相机色彩配置**。用作品集、出版方、博物馆、品牌官方样张或标注拍摄配置的可核验作品。核对作者、胶片型号和配置名称，区分原作品、扫描版本和第三方模拟。

先使用用户指定的搜索入口。未指定时，在豆包工作中优先使用微软必应图片搜索，其他宿主优先使用已经可用的 Chrome + Google 图片搜索。Google 无法打开、请求超时或宿主无法调用它时，切换微软必应。可使用 [必应国内图片入口](https://cn.bing.com/images/search)。Bing 就是微软必应；若 `www.bing.com` 无法访问，可以尝试 `cn.bing.com`，记录为同一服务的另一个入口。

必应也不可用时，依次尝试宿主内置图片搜索、可访问的国内网页搜索和作品官方图集，回到可核验的发布页。国内网页搜索可用百度等宿主实际支持的入口。每个失败入口只作一次有效尝试或更换区域入口，搜索内容最多两轮；记录实际使用的入口、失败原因和可核验出处。没有浏览器控制时可直接用宿主工具。所有入口都不可用时，明确说明未完成网络参考研究；若本地图像编辑和 Python 均可用，可按用户原意加保护约束使用单图路线。图像编辑或本地环境也不可用时，按[环境配置与失败处理](environment_setup.md)停止并报告。原片仅在本地或图像编辑宿主内处理，不提交给搜索引擎。

首轮用中性词寻找代表图，第二轮补足场景或作品并核对出处；已经指定的配色、段落可直接作为查询条件。约 8–12 张独立有效图，尽量来自两个以上的场景或系列。可用更少的可核验样本，并如实记录数量。同组排序完全相同时，优先按出处可靠性排列候选。优先查看小图和页面预览。

## 筛图与按多数选择

1. **确定光照和题材。** 用简短、统一的词分别记录内容图和候选图。例如光照可用「夜景」「阳光」「阴天」「黄昏」「室内人工光」，题材可用「街景」「街拍」「人像」「风光」「建筑」。按画面看得见的光照判断，街拍夜景用「夜景 + 街拍」，晴天人像用「阳光 + 人像」。同义词先统一，例如「肖像」统一为「人像」。原片或候选图的光照判断不清时留空。
2. **只计可归属的作品画面。** 来源优先为电影官方剧照、官方预告中的实际片段、发行方、摄影指导的作品页、电影资料馆或可核对的摄影作品集。排除海报、文字宣传图、幕后、导演或摄影师肖像、演员宣传照、器材商品图、调色教程、来源不明的二次调色、同帧不同裁切或近似连拍。外链搜索缩略图只用于定位发布页。每个独立画面计一次，重复项记录排除理由。无明确配色的有效画面仍计入总数。
3. **先确定多数配色。** 对每张有效图记录可辨冷暖、主要色相、饱和度、肤色及反差，把有区别度且在同一画面中共同出现的关系归为一组。例如「冷青阴影 + 琥珀中间调」作为一组计票，不把来自不同画面的颜色拼成一个风格。分母是全部去重有效图。严格超过半数且跨场景重复时称为多数；唯一领先且跨场景重复时，可标记为未过半的众数。单一场景、并列或仅靠物体本色支撑的倾向不能冒充多数。只给导演名且无跨作品共识时，可按上节选一个有重复证据的作品变体，记录缩小后的统计范围。
4. **再按光照和语义选图。** 只从多数或可信众数的配色组里挑。先选光照、题材都相符的画面，例如夜景街拍配夜景街拍，晴天肖像配阳光下的人像。两项无法都满足时，选至少一项相符的画面，同分时优先光照，再比较共有题材。明确告诉用户哪项不完全匹配。并列配色可以用原片光照和题材选一个有证据的明确作品或段落变体，重新在该范围内计票，并记录它是所选变体。
5. **保留一张主参考及出处。** 保存作品、原发布页、画面定位或可用预览、统计范围、支持数和选择理由。可留另一张独立场景的佐证。若两轮后仍无可信配色，记录原因并使用英文原意和固定保护约束直接编辑；用户不需要补交参考图。

## 让选图结果进入调色任务

由 Agent 把已核对的样张写成 JSON，再交给随 Skill 打包的选择器。选择器根据记录计票和排序，来源真实性、去重及可见配色由实际观察核对。示例仅展示字段，实际任务写真实来源和全部候选。

~~~json
{
  "style_text": "把这张照片调成有点老港片的感觉",
  "source_scope": "港片夜间街拍取样",
  "queries": ["港片 夜晚 街景 剧照"],
  "content": {"light": "夜景", "subjects": ["街拍", "街景"]},
  "candidates": [
    {
      "id": "S01",
      "work": "实际影片名和年份",
      "scene": "能区分不同场景的标识",
      "source_url": "https://example.org/release/stills",
      "locator": "发布页第 2 张或官方预告时间码",
      "light": "夜景",
      "subjects": ["街拍", "街景"],
      "look": "冷青阴影 + 琥珀中间调"
    },
    {"id": "X01", "exclude_reason": "海报"}
  ]
}
~~~

同一组配色使用一致的标签。无可靠标签的有效图将 look 留空。选图结果写到任务外的证据目录，prepare 再将选择结果和哈希记入 job.json。

~~~text
python <skill>/scripts/style_reference_selection.py --candidates out/references/candidates.json --output out/references/selection.json
~~~

把用户原意译成简洁英文，保留专名及明确要求。在可信主参考的基础上补两三条与原片已有色相和明暗相符的定性方向，清楚说颜色往哪边走、强弱如何。可用「蓝灰背景」「清透肤色」「已有红色与深蓝分离」指出颜色关系，但应作用于全图同类颜色。避免自行给出色相角、曝光档、饱和度百分比或精确目标色值。样张中存在的光源、布景、颗粒、物件和局部分色不转写为新内容。

用归纳出的颜色在原片上做同图引导，实际发给 Image 的图一是原片小图，图二是该同图引导。用 `--style-research out/references/selection.json` 连同实际 Prompt 和引导配方调用 [双图准备与提交](image_reference_providers.md)。模型没有多图能力或证据不足时，保留研究记录并按单图提交，说明原因。网上样张的 URL 和选择理由随结果交付。单张外部样图可以有独立预览，但不替代模型实际返回的调色参考，也不直接进入最终套片。
